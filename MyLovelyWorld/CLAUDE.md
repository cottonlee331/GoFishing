## Project overview

MyLovelyWorld is a Unity **2D (URP)** project, freshly created from Unity's "2D Universal" template. There is no game code yet — the only script is the template's `Assets/Welcome/Welcome2DScript.cs` (part of the template's welcome/tutorial page, which can be removed along with `Assets/Welcome/` and the `com.unity.learn.iet-framework` package once no longer wanted).

- Editor version: **Unity 6000.6.6f1** (`ProjectSettings/ProjectVersion.txt`). Open the project with exactly this version.
- Render pipeline: URP 2D renderer (`Assets/Settings/UniversalRP.asset`, `Renderer2D.asset`). New scenes should use `Assets/Settings/Lit2DSceneTemplate.scenetemplate`.
- Input: `activeInputHandler: 1` = **new Input System only**. The legacy `UnityEngine.Input` API will throw at runtime; use `UnityEngine.InputSystem`. The default action asset is `Assets/Settings/InputSystem_Actions.inputactions` (`Player` map: Move, Look, Attack, Interact, Crouch, Jump, Previous, Next, Sprint; plus a `UI` map).
- Installed 2D packages: animation, aseprite & PSD importers, sprite shape, tilemap (+extras), plus Timeline, uGUI, Visual Scripting, Test Framework (see `Packages/manifest.json`).
- Only scene: `Assets/Scenes/SampleScene.unity`.

## Building and testing

There is no CLI build script; building/playing happens in the Unity Editor. `*.csproj`/`*.slnx` files are generated by Unity — don't edit them by hand (they're regenerated on script changes).

Run tests headlessly (the Editor must be closed for this project, since Unity locks it):

```
"<Unity 6000.6.6f1 install>/Editor/Unity.exe" -batchmode -projectPath . -runTests -testPlatform EditMode -testResults ./TestResults.xml
# PlayMode tests: -testPlatform PlayMode
# Single test / fixture: add -testFilter "Namespace.ClassName.MethodName"
```

Test assemblies need their own `.asmdef` referencing `UnityEngine.TestRunner` / `UnityEditor.TestRunner` (none exist yet).

Compile errors and import issues show up in `Logs/` and in `%LOCALAPPDATA%\Unity\Editor\Editor.log`.

## Working with Unity assets

- Every file/folder under `Assets/` has a `.meta` file holding its GUID. When creating, moving, renaming or deleting assets outside the Editor, keep the `.meta` file paired with it (move/rename/delete together); never regenerate or hand-edit GUIDs, or scene/prefab references break. New files created outside the Editor get a `.meta` on next Editor import.
- Scenes, prefabs and `.asset` files are YAML; prefer making changes to them in the Editor rather than editing YAML directly.
- `Library/`, `Logs/`, `Temp/`, `UserSettings/` and generated `*.csproj`/`*.slnx` are machine-local and should not be committed.
