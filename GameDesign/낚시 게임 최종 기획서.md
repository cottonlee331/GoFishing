# 낚시 아케이드(가칭) 기획서

Nov 13, 2026 · @뵤

## 1. 한눈에 보기

제한 시간 동안 판단 입력으로 물고기를 잡아 점수를 겯루는, 한 판 5분 이내의 조선풍 아케이드 낚시 게임이다. Unity 2D로 만들어 exe, WebGL, Android(선택)로 내보낸다.

**핵심 재미**

- **읽고 고르는 판단:** 입질마다 그림자(크기)와 물살을 보고 키를 입력한다.
- **스킬 조합:** 10개 중 3개를 골라 한 판의 전략을 바꾼다.
- **점수 경쟁:** 한 판의 점수를 리더보드에서 비교한다.

**한 판의 흐름**

1. 타이틀
2. 스킬 3개 선택
3. 본편: 낚시를 반복하고, 게이지가 차면 피버에 자동으로 진입한다
4. 시간 종료: "오늘 고기잡이 종료!" 문구
5. 결과 화면: 점수 총합과 포획 목록 (만선이면 "만선이오!")
6. 리더보드 등록 (조건을 충족할 때만)
7. 다시 하기(스킬 선택으로) 또는 타이틀

**시스템 목록**

| ID | 시스템 | 한 줄 역할 | 의존 | 우선순위 |

## 2. 디자인 필러

임의로 기능을 늘리지 않기 위해, 아래 세 가지에 맞지 않는 요소는 넣지 않는다.

| 지킬 가치 | 의미 |
| --- | --- |
| 읽고 고르는 판단 | 입질마다 그림자와 물살을 보고 키를 고른다. 실력은 손 기술이 아니라 판단이다. |
| 5분 안에 끝나는 가벼움 | 스킬 선택부터 결과까지 한 호흡에 끝난다. |
| 빌드로 갈리는 점수 경쟁 | 스킬 3개 조합이 전략을 바꾸고, 결과가 리더보드에서 비교된다. |

| 하지 않을 것 | 의미 |
| --- | --- |
| 타이밍 정밀도·연타 속도를 요구하지 않는다 | 규칙 기반 입력만 쓴다. 모바일에서도 같은 규칙이 통한다. |
| 장기 성장과 재화를 두지 않는다 | 판마다 같은 출발선이어야 점수를 공정하게 비교할 수 있다. |
| 콘텐츠 양으로 승부하지 않는다 | 어종·스킬 가짓수를 늘리는 대신 선택이 의미 있게 갈리는 것에 집중한다. |

## 시스템 1. 게임 흐름과 타이머 (S1)

한 판은 6개 상태를 순서대로 지나가고, 본편의 시간은 하나의 타이머가 관리한다.

| 상태 | 하는 일 | 다음 상태로 넘어가는 조건 |
| --- | --- | --- |
| Title | 시작 버튼 표시 | 시작 입력 → SkillSelect |
| SkillSelect | 스킬 10종 중 정확히 3개를 고른다 (중복 불가, 3개가 아니면 시작 버튼 비활성) | 시작 입력 → Playing |
| Playing | 낚시 반복, 피버 진행 | 라운드 종료 조건 → Ending |
| Ending | "오늘 고기잡이 종료!" 문구 연출 | 연출 끝 → Result |
| Result | 점수 총합과 포획 목록 출력 (S8) | 확인 입력 → 리더보드 흐름(S9) 후 SkillSelect 또는 Title |

**타이머 규칙**

- Playing이 시작되면 `round_time_sec`초를 카운트다운한다. 시간은 timeScale의 영향을 받지 않는 값으로 계산한다.
- 타이머가 0이 되었을 때 피버 중이 아니면 즉시 종료한다. 피버 중이면 피버가 끝나는 즉시 종료한다.
- 종료 시점에 진행 중이던 입질(대기 중, 판단 중 모두)은 취소하고 점수를 주지 않는다.
- 피버 중 타이머가 0이 되면 HUD는 0:00으로 고정하고 피버 남은 시간을 보여준다.
- 일시정지 기능은 없다. 앱 포커스가 빠져도 타이머는 실시간 기준으로 계속 흐른다 (정보 가림은 하지 않는다. 이 처리 자체가 Could).
- 스킬 선택부터 결과 화면까지 한 판은 5분 이내여야 한다.

**사용 데이터:** `round_time_sec`, `fever_duration_sec`

## 시스템 2. 입력과 판정 (S2)

**역할:** 입질이 시작되면 플레이어가 "물살 판단"과 "어종 판단"을 큐에 쌓고, 낚아올리기로 확정해 성공 확률을 정한다. 이 게임의 유일한 조작 시스템이다.

**입력 키**

| 키 | 물살 판단일 때 | 어종 판단일 때 | 기본 단축키 \[가정\] |
| --- | --- | --- | --- |
| 강력 | 강 | 대 | A |
| 무난 | 보통 | 중 | S |
| 섬세 | 약 | 소 | D |
| 낚아올리기 | 확정 | 확정 | Space |

**규칙**

- 입력은 입질이 시작된 순간부터 유효하다. 입질 전(대기 중)의 입력은 무시한다.
- 판정 키(강력/무난/섬세)는 2칸 큐에 쌓인다. 가득 차 있으면 가장 오래된 입력을 밀어낸다 (FIFO).
- 낚아올리기를 누르는 순간 큐의 1번째 = 물살 판단, 2번째 = 어종 판단으로 해석한다.
- 큐가 2칸 미만일 때 낚아올리기를 입력하면 비어 있는 칸은 실패(오답)로 처리한다.
- 입질 시작 후 `judge_time_sec`초 안에 확정하지 못하면 실패(TIMEOUT)다.
- 확정 직후 `confirm_lock_sec`초 동안 모든 입력을 무시한다 (결과 연출 중 오입력 방지).
- 판정 모듈은 입력(큐 2개, 현재 물살, 어종 크기, 어종 크기 보정)과 출력(성공 여부, 부분 점수 여부)만 약속하고 내부는 교체 가능하게 만든다 (이후 타이밍형으로 바꿀 가능성).

**확률 계산**

| 항목 | 값 |
| --- | --- |
| 물살 점수 | 물살 키가 정답이면 1, 아니면 0 |
| 어종 점수 | 크기 키가 정답이면 1, 소형에 무난이면 0.5, 아니면 0 |
| s | 물살 점수 + 어종 점수 (0\~2) |
| 성공 확률 P | min(`p_max`, (`p0` + (`p2` − `p0`) × s / 2) × 난이도 보정 d) |

- 예시: 중형, 물살 정답, 어종 오답이면 s = 1, P = (0.30 + 0.60 × 0.5) × 0.95 = 0.57.
- 소형 + 무난은 부분 정답이며, 성공해도 점수에 `partial_score`를 곱한다.
- 스킬 7(침착)은 오답 키 한 개를 `wrong_key_forgive_prob` 확률로 정답으로 취급한다.

**예외**

- 같은 프레임에 여러 키가 눌리면 먼저 처리된 입력만 받는다.
- 확정 시점의 물살 상태를 기준으로 판정한다. 물살이 바뀌는 순간 입력은 바뀌기 전 상태로 처리한다.

**사용 데이터:** `judge_time_sec`, `p0`, `p2`, `p_max`, `partial_score`, `confirm_lock_sec`, `sizes.difficulty`

**이 시스템에서 하지 않는 것:** 타이밍 미니게임, 키 조합 입력, 입질 전 선입력

## 시스템 3. 입질과 어종 (S3)

**역할:** 캐스팅 후 입질이 오는 시점과 잡히는 물고기를 정한다. 플레이어에게는 그림자 크기만 보이고 어종은 숨겨진다.

**흐름**

| 순서 | 처리 |
| --- | --- |
| 1. 캐스팅 | 자동으로 시작한다 (별도 입력 없음). 크기를 먼저 추첨한다 |
| 2. 대기 | 크기별 `wait_min`\~`wait_max` 사이 랜덤 시간 동안 대기한다 |
| 3. 입질 | 그림자를 표시하고 판정 시간(S2)이 시작된다 |
| 4. 어종 결정 | 크기 안에서 `weight` 비율로 어종을 추첨한다 (플레이어에게는 숨김) |
| 5. 종료 | 성공하면 포획 기록과 점수(S5), 실패하면 기록 없이 다시 1번으로 |

**크기 추첨**

- 기본 비율은 소 66 / 중 28 / 대 6 (`sizes.share`).
- 스킬 6, 8, 10이 비율을 바꾼다. 적용 순서는 6 → 8 → 10이고, 마지막에 합계를 100으로 다시 맞춘다 \[가정\].

**대기 시간**

| 크기 | 최소 | 최대 |
| --- | --- | --- |
| 소 | 1.5초 | 4.0초 |
| 중 | 3.0초 | 7.0초 |
| 대 | 5.0초 | 9.0초 |

- 스킬 5는 대기 시간 ×1.15, 스킬 6은 ×0.8, 피버 중에는 ×`fever_wait_mult`(0.6)를 곱한다. 겹치면 곱셈으로 쌓는다.

**그림자**

- 그림자 크기 = 크기별 `shadow_ratio` × (1 ± `shadow_noise`). 노이즈 때문에 중형과 대형 사이가 헷갈릴 수 있고, 이것이 판단의 재미 요소다.
- 어종 이름과 점수는 포획 후에 처음 공개한다.

**어종 10종**

| 크기 | 어종 |
| --- | --- |
| 소 (5종) | 멸치, 정어리, 망둥어, 붕어, 전어 |
| 중 (3종) | 숭어, 농어, 도미 |
| 대 (2종) | 방어, 철갑상어 |

수치 전체는 `fish.csv` 참고.

**예외**

- 대기 중에 라운드가 끝나면 입질 없이 종료한다.
- 같은 크기가 연속으로 나와도 보정하지 않는다 (순수 랜덤).

**사용 데이터:** `sizes.csv`, `fish.csv`, `fever_wait_mult`, `shadow_noise`

**이 시스템에서 하지 않는 것:** 미끼 선택, 낚시 지점 선택, 어종별 고유 행동

## 시스템 4. 물살 (S4)

**역할:** 판정의 "현재 물살"을 정한다. 플레이어는 물살을 읽고 맞는 키를 눌러야 한다.

**규칙**

| 항목 | 내용 |
| --- | --- |
| 단계 | 강 / 보통 / 약 (3단계) |
| 변화 주기 | `current_period_sec`(30초)마다 무작위로 바뀐다. 스킬 9는 주기를 절반으로 줄인다 |
| 변화 규칙 | 직전과 같은 단계는 나오지 않는다 \[가정\] |
| 예고 | 바뀌기 `current_warn_sec`(0.5초) 전에 HUD가 깜빡인다 |
| 시작 값 | 라운드 시작 시 무작위 |

- 물살은 입질 중에도 흐른다. 판정은 확정 시점의 물살을 기준으로 한다.
- 스킬 9를 쓰면 변화 주기가 절반이 되어 물살이 더 자주 바뀐다. 포획마다 +3점은 S5에서 처리한다 \[가정\].

**예외**

- 변화 시점과 확정이 겹치면 바뀌기 전 물살로 판정한다.
- 피버 중에도 주기는 그대로 흐른다.

**사용 데이터:** `current_period_sec`, `current_warn_sec`

**이 시스템에서 하지 않는 것:** 풍향, 물살 방향, 물살 연출 외 시각 효과

## 시스템 5. 점수와 피버 (S5)

**역할:** 포획 점수를 계산하고, 큰 물고기를 잡을수록 피버 게이지가 빨리 차서 점수 배율이 오르는 구간을 만든다.

**점수 공식**

`포획 점수 = 기본 점수 × 스킬 계수 × 부분 점수 × 피버 배율 + 스킬 9 고정 보너스`

| 항목 | 값 |
| --- | --- |
| 기본 점수 | `fish.csv`의 `base_points` (청상아리는 `shark_points`) |
| 스킬 계수 | 스킬 1(대형 ×1.6), 스킬 2(소형 ×1.4). 같은 키는 곱, 더하는 타입은 합산 |
| 부분 점수 | 소형에 무난을 눌렀을 때 `partial_score`(0.5), 그 외 1 |
| 피버 배율 | 피버 중 `fever_mult`(2.0, 스킬 3이 +0.4), 아니면 1 |
| 스킬 9 보너스 | 포획마다 최종 점수에 +3 (배율에 곱하지 않음) \[가정\] |

- 점수는 정수로 반올림해 표시한다.

**피버**

| 항목 | 규칙 |
| --- | --- |
| 게이지 | 포획 크기별로 소 +10 / 중 +20 / 대 +40 (`gauge_gain`). 스킬 4는 ×1.3 |
| 진입 | `gauge_max`(100)에 도달하면 자동 진입 |
| 지속 | `fever_duration_sec`(20초) 고정 |
| 효과 | 점수 배율 상승, 입질 대기 시간 ×0.6 |
| 중 게이지 | 피버 중에는 게이지가 오르지 않는다 |
| 종료 | 게이지를 0으로 초기화한다 |

- 피버 중에 이미 진행 중인 입질은 새 배율을 그대로 받는다. 피버 시작과 끝은 포획 처리 시점을 기준으로 한다 \[가정\].
- 게이지 초과분은 버린다 (이월하지 않는다) \[가정\].
- 라운드 타이머 종료와 겹치면 피버가 끝날 때까지 계속한다 (S1).

**예외**

- 실패한 입질은 점수와 게이지 모두 얻지 못한다.

**사용 데이터:** `fever_duration_sec`, `fever_mult`, `fever_wait_mult`, `gauge_max`, `sizes.gauge_gain`, `fish.base_points`, `partial_score`, `skills.csv`

**이 시스템에서 하지 않는 것:** 콤보 시스템, 피버 중 다른 이벤트, 피버 중첩

## 시스템 6. 청상아리 (S6)

**역할:** 운과 조합이 맞아떨어질 때만 나오는 특별 보상. 매 판 목표가 있어 "다음 입질이 중요하다"는 기대를 만든다.

**조건**

| 항목 | 기본 | 스킬 8 장착 시 |
| --- | --- | --- |
| 목표 조합 | 소 1 + 중 1 + 대 1 | 대 2 + 중 1 |
| 중복 | 같은 어종은 인정하지 않음 | 동일 |
| 순서 | 상관없음 | 동일 |
| 보상 | `shark_points`(250) | 동일 |

- 포획 성공한 어종이 목표 조합에 해당하면 진행도가 올라간다. 시도 실패는 진행도를 리셋하지 않는다.
- 조합이 완성되면 다음 입질이 청상아리 입질이 된다. 판정은 대형 규칙(난이도 0.85)을 쓰고 점수는 `shark_points`로 지급한다. 피버 배율과 스킬 9 보너스는 적용한다 \[가정\].
- 청상아리 입질에서 실패해도 다음 입질에 다시 나타난다. 잡을 때까지 유지된다 \[가정, 시뮬레이션 기준\].
- 성공하면 진행도를 초기화한다. 한 판에 여러 번 잡을 수 있다 \[가정\].

**UI:** HUD에 3칸 진행도를 표시한다 (잔량이 아니라 어느 크기를 잡았는지 아이콘으로). 스킬 8 장착 시에는 대/대/중으로 바뀐다.

**예외**

- 라운드 종료 시점에 청상아리 입질이 진행 중이면 취소하고 점수는 없다 (S1).

**사용 데이터:** `shark_points`, `skills.csv`(8번 `shark_combo`)

**이 시스템에서 하지 않는 것:** 다른 특별 어종, 보스전, 조합 힌트

## 시스템 7. 패시브 스킬 (S7)

**역할:** 한 판 전에 10종 중 3개를 골라 빌드를 만든다. 재플레이 동기의 핵심이다.

**규칙**

- 정확히 3개, 중복 불가. 라운드 중 변경 불가.
- 효과는 선택한 시점부터 항상 적용된다 (발동 조작 없음).
- 같은 키를 바꾸는 효과는 곱셈, 더하는 타입은 덧셈으로 겹친다.
- 8번(효과: 중·대 비율 ×1.3, 청상아리 조건 변경)과 10번(대 비율 +4%p)은 같이 고를 수 있다. 대형이 자주 나와 6번(소형 위주)과 방향이 서로 다르다.

**10종 효과 요약** (수치는 `skills.csv`)

| ID | 이름 | 분류 | 효과 | 대가 |
| --- | --- | --- | --- | --- |
| 1 | 큰 손 | 점수 | 대형 점수 ×1.6 | 없음 |
| 2 | 알뜰 수확 | 점수 | 소형 점수 ×1.4 | 없음 |
| 3 | 신바람 | 점수 | 피버 배율 +0.4 | 없음 |
| 4 | 불씨 | 시간 | 피버 게이지 획득 ×1.3 | 없음 |
| 5 | 느긋한 낚시꾼 | 시간 | 판정 시간 +1.5초 | 입질 대기 ×1.15 |
| 6 | 재빠른 손 | 시간·출현 | 입질 대기 ×0.8, 소형 비율 +5%p | 없음 |
| 7 | 침착 | 확률 | 오답 키 한 개를 40% 확률로 정답 처리 | 없음 |
| 8 | 묵직한 입질 | 출현 | 중·대 비율 ×1.3, 청상아리 조건 변경 | 없음 |
| 9 | 물살 타기 | 점수 | 물살 변화 주기 ×0.5, 포획마다 +3점 | 없음 |
| 10 | 큰물 욕심 | 위험 | 대 비율 +4%p | 판정 시간 −1.0초 |

- 9번의 +3점은 포획 성공마다 최종 점수에 더하는 고정 보너스로 해석한다 \[가정\].

**예외**

- 고른 스킬이 3개 미만일 경우 선택한 스킬만 적용한 채 게임을 시작한다.&#32;
- 5번과 10번을 같이 고르면 판정 시간이 +0.5초가 된다 (덧셈).

**사용 데이터:** `skills.csv`

**이 시스템에서 하지 않는 것:** 스킬 레벨업, 해금, 라운드 중 교체

## 시스템 8. 결과 화면과 엔딩 (S8)

**역할:** 한 판의 결과를 보여주고, 점수에 따라 엔딩 등급을 정한다. 재플레이 동기를 마지막에 한 번 더 줌다.

**표시 항목**

| 항목 | 내용 |
| --- | --- |
| 총점 | 판 전체 점수 |
| 포획 목록 | 어종별 마릿수, 크기별 합계 |
| 청상아리 | 잡았는지, 몇 번인지 |
| 선택한 스킬 3개 | 아이콘과 이름 |
| 엔딩 등급 | 아래 표 |
| 다음 행동 | 리더보드 등록, 다시 하기, 타이틀 |

**엔딩 등급**

| 등급 | 조건 | 목적 |
| --- | --- | --- |
| 만선 | 총점 ≥ `manseon_threshold`(600) | 좋은 결과에 대한 보상 |
| 그외 등급 | 만선 미만이면 일반 엔딩 | 한 판 마무리 연출 |

- 만선 임계값은 숙련자 평균(약 640) 부근으로 두어 "잡으면 좋은 판"을 만들기 위한 예시다. 플레이테스트로 조정한다.
- 엔딩 연출은 텍스트와 배경 교체 정도로 시작한다. 등급 종류를 늘리는 것은 리소스가 결정된 이후에 판단한다 \[가정\].

**흐름:** Ending("오늘 고기잡이 종료!") → Result → 확인 입력 → 리더보드(S9) → 다시 하기 또는 타이틀.

**예외**

- 포획이 하나도 없으면 총점 0으로 표시하고 리더보드 등록을 안내하지 않는다.

**사용 데이터:** `manseon_threshold`, `result_time_sec`

**이 시스템에서 하지 않는 것:** 도감 모으기, 업적, 엔딩 컷신 사전 제작

## 시스템 9. 리더보드와 저장 (S9)

**역할:** 계정 없이 닉네임과 점수만으로 온라인 순위를 보여준다. 옴라인이면 게임은 그대로 돌아간다.

**구조**

| 항목 | 내용 |
| --- | --- |
| 서버 | Firebase (REST API, UnityWebRequest). Unity Firebase SDK는 데스크톱이 베타이고 WebGL 미지원이라 쓰지 않는다 |
| 저장 형태 | 고정 `board_slots`(10)개 슬롯. 각 슬롯에 닉네임, 점수, 서버 시각 |
| 등록 조건 | 빈 슬롯이 있거나, 내 점수 > 현재 최하점 |
| 덮어쓰기 대상 | 빈 슬롯 중 첫 번째, 없으면 최하점 슬롯 (동점이 여러 개면 가장 최근 슬롯) \[가정\] |
| 동점 | 먼저 달성한 기록이 위에 둔다 (서버 시각 기준) |
| 보안 규칙 | 새 점수 > 기존 점수일 때만 쓰기 허용, 삭제 금지, 타입·범위 검사, 서버 시각 자동 기록 |
| 로컬 | 개인 최고 점수만 저장 |

**흐름**

| 단계 | 처리 |
| --- | --- |
| 1 | Result에서 확인 입력 → 리더보드 조회 (이 조회가 네트워크 확인 역할도 함) |
| 2 | 조회 실패 → 재시도 / 취소 선택. 취소하면 등록 없이 다음 판으로 |
| 3 | 조회 성공 → 내 점수가 등록 조건을 만족하면 닉네임 입력창 표시 |
| 4 | 등록 요청 → 성공/실패 표시 → 순위표 표시 |
| 5 | 등록 조건 미달이면 순위표만 보여준다 |

**닉네임:** `nickname_min`\~`nickname_max`자(2\~8), 한글/영문/숫자, 앞뒤 공백 제거.

**받아들인 제한**

- 한 기기가 여러 슬롯을 차지할 수 있다 (오락실 랭킹 느낌으로 의도).
- 클라이언트 점수 위조는 막지 않는다. 대신 `score_sanity_max`를 넘는 점수는 보내지 않는다.

**예외:** 세부는 문서 하단의 예외 표(네트워크 타임아웃, 중복 제출, 동시 제출, 닉네임).

**사용 데이터:** `board_slots`, `nickname_min`, `nickname_max`, `score_sanity_max`, `net_timeout_sec`

**이 시스템에서 하지 않는 것:** 로그인, 점수 검증 서버, 기록 삭제, 일일·주간 랭킹

## 검증 계획

구현 후 플레이테스트로 수치를 조정한다. 아래는 사전 시뮬레이션(Python 몰테카를로, 빌드당 20,000판)의 결과를 기준선으로 삼는다. 숙련자는 반응 시간이 평균 2.4초, 초보자는 평균 3.5초로 가정했다.

**기준선 (스킬 없이)**

| 지표 | 숙련자 | 초보자 |
| --- | --- | --- |
| 평균 점수 | 약 640 (하위 10% 362 / 상위 10% 1020) | 약 280 |
| 청상아리 달성률 | 약 27% | 약 6.5% |
| 피버 점수 비중 | 약 45% | — |

**가설과 검증 방법**

| # | 가설 | 확인 방법 | 기록할 로그 | 조정 변수 |
| --- | --- | --- | --- | --- |
| H1 | 판단 재미: 숙련자와 초보자 점수 차가 있지만 초보자도 즐길 만하다 | 신규 5명 이상에게 스킬 없이 3판씩 | 판별 점수, 입질별 성공/실패/TIMEOUT 수 | `judge_time_sec`, `p0`, `p2` |
| H2 | 빌드 다양성: 특정 빌드가 독점하지 않는다 | 스킬 선택 비율 집계, 빌드별 평균 점수 | 선택 스킬 3개, 총점 | `skills.csv` 값 |
| H3 | 피버 적정성: 피버 점수 비중이 55% 이하, 판당 피버 1\~2회 | 피버 진입 횟수와 피버 중 획득 점수 | 피버 시작 시각, 피버 중 획득 점수 | `fever_duration_sec`, `fever_mult`, `gauge_gain` |
| H4 | 청상아리는 숙련자 25\~30%, 초보자 5\~8% 수준에서 운과 기술이 섞인다 | 청상아리 달성률 집계 | 조합 진행도, 달성 시각 | `sizes.share`, `shark_points` |
| H5 | 지연 전략: 끝까지 버티는 플레이는 이득이 없다 | 확정 시간 분포 비교 | 입질 시작 대비 확정 시각 | `judge_time_sec` |

**조정 후보 (현재는 적용하지 않음)**

| 신호 | 후보 |
| --- | --- |
| 정보/점수, 소형 속사가 다른 빌드보다 확실히 높음 | 스킬 9 보너스 3→2, 스킬 1 ×1.6→1.5, 스킬 2 ×1.4→1.3 |
| 피버 올인의 피버 비중이 55%를 넘음 | 스킬 4 ×1.3→1.2 또는 스킬 3 +0.4→+0.3 |
| 초보자 평균이 기준선에 크게 못 미침 | `p0` 상향 또는 `judge_time_sec` 증가 |

**비교 방법:** 구현 후 같은 지표를 수집해 위 기준선과 나란히 놓는다. 시뮬레이션과 20% 이상 차이가 나면 실제 플레이 데이터를 따르고 가정(반응 시간 분포 등)을 수정한다.
